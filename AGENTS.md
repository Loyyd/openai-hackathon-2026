# Repository workflow

- Update the relevant README or documentation when changing setup, behavior, or interfaces.
- Run the checks appropriate to the change and report their results.
- After completing a requested repository change, commit the task's files and push the working branch without waiting for another reminder. Leave unrelated user changes untouched.
- Use a branch appropriate to the task. If the previous branch's pull request has already merged, start a new branch from the latest `origin/main`. Do not push changes directly to `main` or force-push unless explicitly requested.
- When a pull request is part of the task, create or update it with an accurate description and validation results. Do not merge it without authorization.
- Before finishing, verify the pushed commit matches the local branch and report the branch, commit, pull request link when applicable, and any remaining local changes. Clearly state if a check, commit, or push could not be completed.
